## The problem (audited 2026-07-02 against the doctrine brief)

The focused pane's gnode path is snapshot-and-diff where the doctrine says delta-and-fold. Gyre knows the per-tick delta (which nodes moved; selection and hover are single events), and the pipeline discards it twice:

1. **Meerkat rebuilds the world each frame.** `render_orrery_scene` constructs a full `Vec<OrreryGnode>` per frame, `PartialEq`s it against last frame's, and on any change re-runs the whole orrery view, re-formats every gnode's inline style strings, and lets the view diff re-derive the mutation set gyre already had.
2. **Stable data is re-derived per frame.** Verified: `favicon_data_uri` PNG-encodes + base64s on every call (`render/textures.rs:69`, no cache), and the snapshot calls it per node per frame — an idle settled graph pays N PNG encodes per frame to conclude "unchanged." Same per-frame churn for the label `String`, `color` `String`, sprite data-URI clone, and hull `to_vec`.
3. **Hover poisons the equality gate.** `hovered` is a snapshot field, so any mouse motion over the pane flips one bool and invalidates the whole compare, triggering a full view re-run over every gnode.
4. **Downstream, paint emission ignores delta size** (ui_polish finding 5, measured: `chrome_us` 100-145ms whether 16 or 203 mutations). That is genet-layout's `emit_paint_list` re-walking the whole box tree; it is out of scope here and stays the dominant frame-time term until its own fix lands.

Meanwhile the **secondary panes' in-scene pool** (`orrery/build.rs` + `frame.rs`) is already doctrine-shaped: an id→`DomNodeId` table built once ("never rebuilt structurally"), per-frame value→value transform/class writes for exactly the changed nodes, engineered to stay on the RepaintOnly path. The focused pane traded that shape away in the orrery-as-element migration to buy unified-document wins (one focus ring, one a11y tree, theming). This plan keeps those wins and restores the shape: the pool lives **inside the shell document**, host-managed.

Host-direct writes to the shared shell DOM are established practice (`render/overlays.rs` patches overlay geometry styles post-layout), and all host writes drain through the same `drain_mutations` → `IncrementalLayout::apply` path the view's writes do — so pool mutations reach layout identically; transform/class value→value writes classify paint-tier (the in-scene pool proves this daily).

## Honest scope statement

This plan recovers the **meerkat-side** waste: per-frame snapshot construction, whole-world PartialEq, full view re-runs, string/PNG churn, and mutation volume. It does **not** move `chrome_us` much until genet-layout's paint-emission fix lands (finding 5's own track): emit cost scales with document size, not mutation count, and the gnodes stay in the shell document by design. The two fixes are complementary halves of the same clause-6 restoration; neither substitutes for the other. P0 exists to make both halves measurable separately.

## Phases

### P0 — Instrument before surgery (doctrine §6.3)

Per-frame integers, surfaced via the existing `meerkat::profile` trace target (and later the apparatus panel, converging with the graph-delta plan's Phase D): snapshot build µs, view re-run bool + µs, gnode count, shell-document node count, favicon encodes this frame, shell-session rebuild/structural flags, and a **pool-local** mutation breakdown (`pool_structural_inserts`, `pool_structural_removes`, `pool_hot_attr_writes`, `pool_stable_attr_writes`). Total `DomMutations` drained stays as secondary context, not the success metric, because unrelated shell churn can move it independently of the gnode path. **Landed.** Code landed, fresh headed workbench drag / tear-out verification is landed, and the idle plus pan/hover/select capture sessions are now recorded in Progress.

### P1 — Stop the bleeding (no architecture change)

Cheap fixes that stand alone even if the pool slipped:

- Cache favicon data-URIs per node, invalidated when `favicon_rgba` changes (it is stable kind-data; encode once). **Landed in `GnodePool::cached_favicon`.**
- `color` becomes `&'static str` (it already is at the source; the snapshot `to_string()`s it). **Landed.**
- Cache the derived label per node keyed by title; stop re-slicing/re-allocating per frame. **Landed in `GnodePool::cached_label`.**
- Sprite URI and hull move behind `Arc` (or a per-member cache) instead of per-frame clones. **Landed in `GnodePool::cached_sprite` / `cached_hull`.**
- Pull `hovered` out of the snapshot equality: hover becomes its own cheap channel (host writes the wash class directly on hover change), so mouse motion stops invalidating the world. **No longer needed for the old `OrreryRender.gnodes` compare gate, because that gate is already gone; hover still flows through the per-frame pool fold.**

Done when an idle settled frame performs zero PNG encodes and near-zero allocations in the snapshot path (P0 counters confirm), and hover-only motion no longer forces whole-snapshot inequality.

### P2 — The seam: a host-owned container the view never diffs into

A small `xilem_serval` addition: a view (working name `host_pool(id)`) that builds a container element and guarantees the view layer never touches its **children** (the view may still own the container's own attrs/position). The host injects and mutates children directly in the shared `ScriptedDom`.

The view stamps a stable host-pool identifier (for example `data-host-pool="orrery-gnodes"`) so the host can rebind the pool root after a shell rebuild. The pool state is per `WindowView`, not in `ShellState` and not graph-global: it owns `NodeId`s in one window's `ScriptedDom`, so it must clear/rebind when that DOM or container node changes.

Verification is the deliverable: an xilem-serval test that (a) builds a view tree containing the container, (b) host-appends children directly to the DOM, (c) rebuilds the view several times with surrounding siblings changing, and (d) asserts the host children survive untouched and sibling diffing stays correct. The risk to rule out is index-based `ElementSplice` operations on the parent walking into host-owned children. If the bare `el(tag, ())` with no view children already has this property, `host_pool` is a documented alias plus the test; if not, it is a real leaf-view. Done when the test passes both scenarios.

### P3 — The gnode pool

Host-side `GnodePool`, the in-scene pool's shape lifted into the shell document under the P2 container:

- **Table**: `member → NodeId` plus per-member cached columns split hot/stable. Hot (compared per frame, plain scalars): x, y, size, lift, selected, hovered, state-color class, z/depth. Stable (written on change only): label, favicon URI, sprite URI, hull clip-path, radius class. **Landed:** `GnodePool` entries now cache hot/stable row columns and setter helpers suppress unchanged writes.
- **Ownership / ordering**: store the pool on `WindowView` beside `chrome_session`, run it in `render_orrery_scene` after `orrery.frame(...)` has produced this-frame positions and before `render_chrome_scene(...)` drains the shell DOM. The orrery view becomes `(scene, host_pool("orrery-gnodes"), focus_card)`, preserving the current z-order. **Landed.**
- **Membership reconcile** on scope/cull/graph change: create + append element (face img, caption, wash as children) for entrants; park off-pane members behind a hidden attr on viewport cull; remove only when the pool root or bound graph changes. This keeps ordinary cull/return churn on the attribute path that `PaneSession` can fold cheaply. **Landed.** Focused tests now prove the park/return batches drain as attribute-only mutations.
- **Per-frame fold**: compare each member's hot columns against the cached row (cheap f32/bool compares, zero allocation); write only changed values — transform for movement, class flips for state/selection/hover. A settled graph writes nothing. This derives the delta by table compare, needing no new orrery API; if profiling later favors it, gyre can expose a moved-set directly (deferred). **Landed.**
- **Styling moves from inline strings to sheet classes** (a `GNODE_SHEET` block folded into the chrome sheet): per-frame writes shrink to transform + class attribute values, and gnode styling becomes reachable by `scale_px`/`ui_scale` — directly serving ui_polish finding 1/P5 (canvas text scaling) as a side effect. Per-node-variable bits (size px, hull polygon) stay inline. **Landed in `gnode_pool.rs` + `theme_sheets.rs`; the root now carries only geometry style and the face/label/image/wash state rides stable classes/data attrs.**
- **OrreryRender shrinks** to `rect` + `focus_card`: the focus-card family stays view-shaped (summonable, low-frequency, correct as diffed views); the always-there gnodes stop being view state. **Landed.**
- **Tear-out behavior**: pools are per window, while the orrery/graph authority follows the tear-out binding. A plain leaf has no orrery pane, so it usually creates no gnode pool at all. A branch window gets its own `GnodePool` in its own shell document, backed by the donor's same pooled `Orrery`; the existing branch scope install/restore drives which members that window's pool reconciles. A fork gets its own `GnodePool` backed by the fork's new `GraphId`/`Orrery`. No tear-out copies DOM nodes or `NodeId`s across windows. **Seam unchanged; fresh headed leaf / branch / fork verification is landed.**
- **Unchanged by construction**: a11y (`orrery_a11y_tree` reads `.gnode` divs + fragments from the same document), input (gyre owns presses; gnodes stay pointer-inert), z-stack (container before focus card before chrome in document order), theming.

Done when: headed pan/hover/select behaves identically to today (shots compared), `cargo test -p meerkat` green with the snapshot-path tests rewritten against the pool, the pool survives shell rebuilds without orphaning or duplicating gnodes, leaf/branch/fork tear-outs preserve their current behavior, and the **pool-local** counters show structural work proportional to membership churn, hot writes proportional to changed nodes, and zero pool writes when settled. **Landed.** Code, focused tests, fresh headed tear-out validation, and the broader P5 counter capture/write-up are all now in.

### P4 — Retire the snapshot path

Delete `OrreryGnode`, `OrreryRender.gnodes`, `gnode_view`'s per-frame construction (the anatomy moves into the pool's element builder), and the whole-snapshot PartialEq gate. Re-scope the [keyed_view_sequence_plan](../../archive_docs/2026-07-03_completed_plans/2026-07-02_keyed_view_sequence_plan.md) to roster/list-pane/gloss rows only: its orrery consumer is now a temporary bridge, already landed, and this plan removes that one consumer without touching the rest. Done when no per-frame `Vec<OrreryGnode>` exists and the keyed plan's doc reflects the re-scope.

### P5 — Measure against baseline + record

Re-run P0's two capture sessions. Record: snapshot/view numbers, pool-local mutation numbers, and `chrome_us` before/after with the honest attribution (expected: meerkat-side snapshot/pool numbers collapse; `chrome_us` moves only modestly until the genet-layout emission fix). Keep total drained `DomMutations` in the table as context only. Feed the residual straight into that genet-side plan as its motivating measurement. **Landed for the gnode seam.** Idle, hover/select, pan/cull, and post-fix shell-partition numbers are now recorded in Progress below. The remaining handoff caveat is measurement quality, not implementation scope: the Genet-side plan still needs a like-for-like loaded-session capture before its motivating number is stable.

## Open questions

- **OQ-1 Movement epsilon**: write transforms on any f32 change, or only past a sub-pixel threshold (physics micro-settle can jitter positions)? If thresholded, the cutoff is a setting, not a constant.
- **OQ-2 Hover channel**: host-applied class on hover change (proposed) vs keeping hover in the per-frame fold — both are cheap post-P3; pick by code simplicity.
- **OQ-3 Cull policy**: resolved in favor of parking. Off-pane gnodes now stay in the pool with `data-parked='true'`, so viewport cull/return churn stays attribute-only and does not force the shell-session structural rebuild path. The cost is a somewhat larger retained DOM plus explicit a11y filtering for parked rows, which is now wired in. The older `pool_structural_removes=1` / `rebuild=true` / `chrome_us=47748` capture remains the pre-fix baseline, not the current policy; the fresh parked-policy capture showed `pool_structural_removes=0`, `rebuild=false`, `structural=false`, and `shell_node_count=63` on the first off-pane frame.
- **OQ-4 Secondary panes**: converge them onto the same shell-document pool later (one gnode implementation, per-pane containers), or keep the in-scene tier for cheap non-focused panes? No forcing function yet; revisit after P5's numbers.
- **OQ-5 The engine-side form**: unified-document-host cond-1 (a real custom-layout `<orrery>` element, engine-owned placement) remains the eventual genet-side shape; this pool is its host-side realization. Decide after finding 5's fix whether cond-1 still buys anything the pool does not.
